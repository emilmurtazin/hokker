# ХОККЕР — бэкенд, Этап 1 (шаг 1: инфраструктура)

Это первый шаг разработки — голый каркас проекта: FastAPI-сервер. Пока в нём нет
ни одной "боевой" функции — это фундамент, на котором в следующих шагах появится
регистрация, каталог тренеров, тренировки и т.д.

Проект можно запускать двумя способами:
- **Локально** — через `docker-compose.yml` (PostgreSQL и Redis поднимаются как
  контейнеры прямо у вас на компьютере, ничего платить не надо).
- **На Timeweb Cloud App Platform** — через `Dockerfile`, с отдельными
  управляемыми PostgreSQL и Valkey (Redis). Это готовый рабочий вариант,
  инструкция ниже.

## Способ 1: локальный запуск (для разработки)

### Что нужно установить (один раз)

1. **Docker Desktop** — https://www.docker.com/products/docker-desktop/

### Как запустить

```bash
cd hokker-backend
cp .env.example .env
docker compose up --build
```

Проверка: http://localhost:8000/health и http://localhost:8000/health/db

## Способ 2: деплой на Timeweb Cloud App Platform (production)

Здесь мы НЕ используем `docker-compose.yml` — App Platform запрещает `volumes`
в манифесте Docker Compose, а без них PostgreSQL будет терять данные при каждом
перезапуске контейнера. Поэтому база данных и Redis выносятся в отдельные
управляемые сервисы Timeweb, а деплоится только сам API — через `Dockerfile`.

### Шаг 1. Создайте облачную базу данных PostgreSQL

В панели Timeweb: **Облачные базы данных** → Создать → PostgreSQL.
Запомните/скопируйте после создания: хост, порт, имя БД, пользователя, пароль
(или сразу строку подключения — она обычно показывается целиком).

### Шаг 2. Создайте Valkey (аналог Redis)

Там же: **Облачные базы данных** → Создать → Valkey.
Аналогично сохраните строку подключения.

### Шаг 3. Создайте приватную сеть

При создании обеих БД (или после, в разделе «Сети» → «Приватные сети») добавьте
их в одну приватную сеть, например `hokker-network`. Так к ним не будет доступа
из интернета — только от сервисов внутри этой сети.

### Шаг 4. Задеплойте API через App Platform

1. **App Platform** → Создать приложение → тип **Dockerfile**.
2. Подключите ваш GitHub-репозиторий `hokker-backend`.
3. Выберите ветку `main`.
4. На шаге региона/конфигурации — любой минимальный тариф достаточно для старта.
5. На шаге приватной сети — **выберите ту же `hokker-network`**, что и у БД.
   Это единственный способ API достучаться до PostgreSQL/Valkey без выхода
   в открытый интернет.
6. На шаге переменных окружения (`ENV`) укажите:
   - `DATABASE_URL` — строка подключения к вашей PostgreSQL (из шага 1)
   - `REDIS_URL` — строка подключения к вашей Valkey (из шага 2)
   - `JWT_SECRET_KEY` — сгенерируйте случайное значение, например через
     https://www.uuidgenerator.net/ или любой генератор паролей
7. Запустите деплой, дождитесь окончания в логах.
8. Проверьте `https://ваш-технический-домен/health` и `/health/db`.

### Что дальше

Каждый `git push` в ветку `main` (после подключения автодеплоя, он включён
по умолчанию) будет автоматически пересобирать и перезапускать приложение —
вручную заходить на сервер не нужно.

## Шаг 2: модель данных и миграции (готово)

Добавлены SQLAlchemy-модели и первая Alembic-миграция для таблиц:
`users`, `coaches`, `players`, `coach_players`, `arenas` (задел под Этап 4),
`training_sessions`, `bookings` (с полным жизненным циклом листа ожидания).

**Миграции применяются автоматически** при каждом запуске контейнера —
через `entrypoint.sh` (`alembic upgrade head`, затем старт сервера).
Значит, после `git push` на Timeweb App Platform достаточно дождаться
пересборки — таблицы создадутся в вашей PostgreSQL сами, ничего вручную
прогонять не нужно.

Миграция реально протестирована (накат и откат) на локальной PostgreSQL
перед тем, как передать её вам.

### Создать новую миграцию в будущем

Когда в моделях появятся изменения:

```bash
docker compose exec api alembic revision --autogenerate -m "описание изменения"
docker compose exec api alembic upgrade head
```

## Шаг 3: авторизация (готово)

Реализована регистрация и вход по SMS-коду + JWT (access + refresh),
с возможностью отзыва refresh-токена (logout).

**Эндпоинты:**

- `POST /auth/request-code` `{phone}` → `{request_id}` — запросить SMS-код
- `POST /auth/verify-code` `{request_id, code}` →
  - если номер уже зарегистрирован: `{status: "logged_in", access_token, refresh_token, user}`
  - если номер новый: `{status: "registration_required", registration_token}`
- `POST /auth/register` `{registration_token, role, name, city}` → токены
- `POST /auth/refresh` `{refresh_token}` → новый `access_token`
- `POST /auth/logout` `{refresh_token}` → 204, токен отозван
- `GET /users/me` (требует `Authorization: Bearer <access_token>`) → текущий пользователь

**SMS-провайдер пока не подключён** — используется dev-заглушка, которая
печатает код в логи контейнера (`[DEV SMS] Код для +7...: 1234`) и
дополнительно возвращает его в ответе API в поле `debug_code`
**только при `ENVIRONMENT=local`**. На проде (Timeweb) сейчас
`ENVIRONMENT` не задан явно, значит там `debug_code` уже не будет
приходить — но реальные SMS тоже пока не уходят, только лог.
Когда решите подключить настоящего провайдера (SMS.ru и т.п.) —
это единственное место в коде, которое нужно доработать:
`app/services/sms.py`.

**Защита от подбора и спама:**
- код живёт 5 минут, максимум 5 попыток ввода
- не больше 3 запросов кода на номер за 10 минут (429 при превышении)

Весь флоу (регистрация, повторный логин, refresh, logout, отзыв токена,
rate limit, неверный код, повторное использование кода) протестирован
end-to-end перед тем, как передать его вам — реальными HTTP-запросами
к работающему приложению с настоящей PostgreSQL.

## Telegram-бот: меню и уведомления (готово)

### Что видит пользователь

После привязки Telegram (Профиль → «Привязать Telegram») бот присылает
постоянную клавиатуру под полем ввода — набор кнопок зависит от роли. Каждая
кнопка открывает нужный раздел приложения прямо внутри Telegram одним нажатием:

| Роль | Кнопки |
|---|---|
| Родитель | Расписание · Тренеры · Упражнения · Профиль |
| Тренер | Тренировки · Ученики · Лёд · Упражнения · Профиль |
| Администратор арены | Слоты · Заявки · Профиль |

Кнопка «Меню» слева от поля ввода показывает команды (одни и те же для всех
ролей, ответ зависит от роли): `/menu` — вернуть клавиатуру, `/schedule` —
ближайшие тренировки (у арены — слоты), `/requests` — заявки и приглашения,
`/exercises`, `/profile`, `/help`. Дополнительно: `/whoami` (к какому аккаунту
привязан чат) и `/unlink` (отвязать Telegram и отключить уведомления).

Команды `/schedule` и `/requests` показывают данные прямо в чате, а не просто
дают ссылку.

### Какие уведомления приходят

| Событие | Кому |
|---|---|
| Новая заявка / новая запись / отмена записи (с именем ученика) | Тренеру |
| Заявка на лёд подтверждена / отклонена | Тренеру |
| Запись подтверждена / отклонена тренером | Родителю |
| Освободилось место в листе ожидания (15 минут на подтверждение) | Родителю |
| Время на подтверждение места истекло | Родителю |
| Тренировка отменена / **перенесена или изменено место** | Родителю |
| **Напоминание о тренировке** (за `REMINDER_HOURS_BEFORE` часов) | Родителю |
| Тренер добавил в базу учеников · новые оценки | Родителю |
| Новая заявка на лёд / заявка отменена тренером | Администратору арены |

Под каждым уведомлением есть кнопка, которая открывает нужный экран
(например, тренер по новой заявке попадает сразу на страницу тренировки).
Время в сообщениях показывается в часовом поясе `APP_TIMEZONE`
(по умолчанию Москва), типы тренировок — по-русски («Лёд», «ОФП»).

### Что нужно настроить

1. В переменных окружения задать `APP_PUBLIC_URL` — **HTTPS-адрес фронтенда**
   (Telegram открывает Web App только по https), а также `TELEGRAM_BOT_TOKEN`,
   `TELEGRAM_BOT_USERNAME`, `TELEGRAM_WEBHOOK_SECRET` (и `TELEGRAM_PROXY_URL`
   на российском сервере). Полный список новых переменных — в `.env.example`.
2. Вебхук настраивается один раз, как и раньше (`set_webhook` в
   `app/services/telegram.py`, адрес `/internal/telegram/webhook`).
3. Меню команд, описание бота и кнопка «Меню» **настраиваются автоматически при
   каждом старте приложения** — вручную в BotFather ничего делать не нужно.
   Если в BotFather раньше была задана кнопка меню — она будет заменена
   (`TELEGRAM_MENU_BUTTON=commands` — список команд, `webapp` — сразу приложение).
4. Миграция `c3d4e5f6a7b8` добавляет в `bookings` поле `reminder_sent_at`
   (применяется автоматически через `entrypoint.sh`).

### Фоновые задачи

Отдельный воркер и Celery не нужны: раз в минуту внутри процесса API работает
планировщик (`app/services/scheduler.py`), который:

- переводит просроченные приглашения из листа ожидания в `expired`, сообщает
  родителю и предлагает место следующему в очереди (раньше это происходило,
  только если родитель сам нажимал «Подтвердить» после срока);
- отправляет напоминания о тренировках (не в «тихие часы», не тем, кто записался
  меньше чем за `REMINDER_HOURS_BEFORE` часов до начала, и не более одного раза).

Дублей не будет, даже если приложение запущено в нескольких копиях. Выключить
планировщик: `SCHEDULER_ENABLED=false`.

### Важно знать

- Внутри Telegram приложение открывается в собственном браузерном окне со своим
  хранилищем: при первом открытии кнопкой из бота нужно один раз войти по SMS,
  даже если в обычном браузере вы уже авторизованы.
- Если у пользователя нет привязанного Telegram, уведомления молча пропускаются.
- Уведомления отправляются в фоне и не замедляют ответ API; если Telegram
  временно недоступен, сообщение теряется (повторной отправки нет).

## Каталог упражнений (ОФП-01 … ОФП-38)

Список из файла «Каталог упражнений.xlsx» загружается миграцией
`d4e5f6a7b8c9`: названия, место (лёд / зал / вне льда), короткое описание,
число игроков, время, инвентарь, «шайба» и развиваемые качества — с
иллюстрированных карточек. Возраст у всех упражнений — **6–9** (как в
возрастных категориях приложения), хотя на карточках указано «7–9» / «7–10».

- Обновление идёт по коду (`ОФП-01` …): всё, что было изменено вручную в этих
  записях, миграция перезапишет. Пошаговые инструкции, подсказки и «связь с
  хоккеем» у ОФП-01…05 она не трогает.
- ОФП-06…38 пока «черновики»: в приложении видны описание, параметры и качества,
  а подробная инструкция помечена как «скоро».
- Фильтры каталога — по месту и по возрастной категории
  (`GET /exercises?location=gym&age_group=6-9`; знак `+` в `13+` передаётся как `%2B`).

### Иллюстрированная карточка

Если у упражнения заполнено `image_url`, на его странице появляется переключатель
«Карточка / Текстом»; карточка открывается на весь экран и увеличивается по
нажатию. Сейчас подключена карточка ОФП-01. Чтобы подключить другую:

1. Сохраните картинку во фронтенде: `public/exercise-cards/ofp-02.webp`
   (WebP ~1024×1536, качество 90 — около 250 КБ вместо 1,7 МБ у PNG).
2. Укажите путь в базе: `UPDATE exercises SET image_url = '/exercise-cards/ofp-02.webp' WHERE code = 'ОФП-02';`

Папку для картинок нельзя называть `exercises`: это маршрут приложения
(`/exercises`), и nginx при прямом открытии ссылки вернёт 403 вместо приложения.

## Создание платформенного администратора (для загрузки видеоупражнений)

Роль `admin` нельзя получить через обычную регистрацию (это специально —
чтобы никто посторонний не мог сам себя назначить администратором).
Создаётся отдельным скриптом с прямым доступом к базе:

```bash
python scripts/create_admin.py +79991234567 "Имя Администратора"
```

Запускать там, где есть доступ к `DATABASE_URL` (см. `.env`) — то есть
либо локально при локальной разработке, либо через консоль/exec на сервере,
если App Platform такое предоставляет, либо временно включив публичный IP
у облачной БД, подключившись к ней с компьютера, и выключив обратно после.

После создания администратор просто входит в приложение как обычно —
через `/auth/request-code` + `/auth/verify-code` по указанному телефону
(регистрацию через `/auth/register` проходить не нужно, пользователь уже создан).
