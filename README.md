# ХОККЕР — бэкенд, Этап 1 (шаг 1: инфраструктура)

Это первый шаг разработки — голый каркас проекта: FastAPI-сервер, PostgreSQL, Redis,
всё поднимается через Docker. Пока в нём нет ни одной "боевой" функции — это фундамент,
на котором в следующих шагах появятся регистрация, каталог тренеров, тренировки и т.д.

## Что нужно установить (один раз)

1. **Docker Desktop** — https://www.docker.com/products/docker-desktop/
   Скачайте под вашу ОС (Windows / Mac), установите, запустите. Значок кита должен
   появиться в трее/меню-баре — значит, всё работает.

2. Больше ничего устанавливать не нужно — Python, PostgreSQL и Redis будут жить
   *внутри* Docker-контейнеров, на вашем компьютере ничего этого руками ставить не надо.

## Как запустить проект

Откройте терминал (на Mac — приложение "Терминал", на Windows — PowerShell) и перейдите
в папку проекта:

```bash
cd путь/до/папки/hokker-backend
```

Скопируйте файл с настройками:

```bash
cp .env.example .env
```

(на Windows в PowerShell: `copy .env.example .env`)

Запустите всё одной командой:

```bash
docker compose up --build
```

Первый запуск займёт пару минут — Docker скачает образы PostgreSQL/Redis и соберёт
образ вашего API. В логах должно появиться что-то вроде:

```
api_1  | INFO:     Uvicorn running on http://0.0.0.0:8000
```

## Как проверить, что всё работает

Откройте в браузере:

- http://localhost:8000/health — должно вернуть `{"status":"ok"}`
- http://localhost:8000/health/db — должно вернуть `{"status":"ok","database":"connected"}`
  (это значит, что API реально достучался до PostgreSQL)
- http://localhost:8000/docs — автоматическая документация API (Swagger),
  пока пустая, но именно сюда мы будем добавлять все эндпоинты

Если оба `/health`-адреса отвечают ok — шаг 1 завершён успешно, можно переходить
к шагу 2 (модель данных и миграции).

## Как остановить

В терминале, где запущен `docker compose up`, нажмите `Ctrl+C`.
Чтобы полностью остановить контейнеры:

```bash
docker compose down
```

Данные в PostgreSQL при этом сохранятся (они лежат в Docker volume). Если захотите
удалить вообще всё, включая данные — `docker compose down -v`.

## Структура проекта

```
hokker-backend/
├── docker-compose.yml       # описание трёх сервисов: api, db (Postgres), redis
├── Dockerfile                # как собрать образ API
├── requirements.txt          # Python-зависимости
├── .env.example               # шаблон переменных окружения (скопировать в .env)
├── alembic.ini                # конфиг для миграций БД
├── alembic/
│   ├── env.py                 # связывает Alembic с моделями и настройками
│   └── versions/               # сюда будут падать файлы миграций (шаг 2)
└── app/
    ├── main.py                 # точка входа FastAPI, здесь регистрируются роуты
    ├── core/
    │   ├── config.py            # чтение настроек из .env
    │   └── database.py          # подключение к PostgreSQL
    ├── models/                  # SQLAlchemy-модели таблиц (наполним на шаге 2)
    ├── schemas/                 # Pydantic-схемы запросов/ответов API
    └── api/                     # роуты API, сгруппированные по модулям
```
